# Mercury macOS app icon sources

`AppIcon.icon` is the editable Icon Composer package for Mercury's macOS app
icon. Its two SVG layers reconstruct the original Mercury artwork without the
large, GIMP-specific source directory that was removed during the Firefox 153
migration:

- `Assets/background.svg` is the purple background shape.
- `Assets/beaker.svg` is the cyan foreground shape.

Both layers are normalized to the current 1024-by-1024 Mercury vector geometry.
Their separation reconstructs the two-layer `Beaker.svg`/`Background` design
stored in `logos/Mercury.xcf` before commit
`44271524337f079b9da04871a2ffeaeef3cf501b` removed the redundant `logos/`
directory.

The package intentionally contains only Mercury-owned vector artwork. The
generated catalog is checked in as `../Assets.car`; Firefox 153's native macOS
packaging copies it into the application and selects its `AppIcon` entry through
`CFBundleIconName`. The checked-in `../firefox.icns` remains the legacy fallback.

The current catalog was generated by workflow run
`https://github.com/gz83/Mercury/actions/runs/31301665218` from Mercury commit
`eb0f7da4d9cfa354250617ddf96134c7db12f35f`, using Xcode 26.6 (build 17F113),
the macOS 26.5 SDK, and a 10.15 deployment target. Its SHA-256 is
`e14202613c1fa5fb22ed144dc2a6406e25faa750d5b7c64f711670df09358dee`.

Apple does not publish the `icon.json` schema as a stable API. Open this package
with the pinned Icon Composer/Xcode version before changing composition
settings, and review the resulting diff rather than silently accepting schema
rewrites. Do not check Xcode build directories into this source directory. Only
replace `../Assets.car` with the validated workflow artifact, and update the
provenance and SHA-256 above at the same time. Before publishing a replacement,
visually verify its default, dark, and tinted appearances on macOS 26, plus the
legacy `firefox.icns` fallback on an older supported macOS release.

The three `.iconset` directories are editable sources for Firefox 153's legacy
ICNS inputs. `LegacyAppIcon.iconset` produces the application fallback
`../firefox.icns`, `DocumentIcon.iconset` produces the file-association icon
`../document.icns`, and `DiskIcon.iconset` produces the mounted installer-volume
icon `../disk.icns`. Each contains all ten standard 1x and 2x PNG renditions from
16 through 1024 pixels.

Run the manually dispatched `rebuild-macos-legacy-icons.yml` workflow after
changing any rendition. The workflow uses Apple's `iconutil`, unpacks all three
results again to verify every size, and uploads the ICNS files plus hashes and
provenance as a single artifact; it never modifies the repository. Replace the
three checked-in files only with validated workflow artifacts. Before release,
verify the legacy application and document icons on an older supported macOS
version and visually inspect a mounted Mercury DMG in Finder.
